# Go Guard Rail Hook Plan

**Goal:** Run the guard rail hook on Windows. Move every decision the hook makes out of `hooks/clusage-guard.sh` and into a `clusage hook run` subcommand, so one Go implementation serves macOS, Linux and Windows. The per-platform files shrink to wrappers of one line.

**Why now:** clusage ships in the [wolffshots/scoop-bucket](https://github.com/wolffshots/scoop-bucket) bucket (`bucket/clusage.json`). The binary and the status line work there. `clusage hook install` does not, for four reasons:

1. The release publishes only the binary. `clusage-guard.sh` is not a release asset, so `hookScript()` in `hook.go` finds nothing on a Scoop install.
2. The script needs bash, awk, `date` and python3. Claude Code on Windows has Git Bash, but python3 is often missing, and the `--install` path needs python3 to edit `settings.json`.
3. `--install` makes a symlink at `~/.claude/hooks/clusage-guard.sh`. Windows allows symlinks only in Developer Mode or as an administrator.
4. Paths assume Unix: the stamp is `${TMPDIR:-/tmp}/clusage-guard-$USER.stamp`, and every deny tells the user to run `touch` or `rm` on the off switch.

## Current Shape

| Piece | Where | Language |
|---|---|---|
| Event dispatch, payload read | `hooks/clusage-guard.sh` | bash |
| Resume report (SessionStart) | `report_resume` in the script | python3 inside bash |
| Poll ramp and projection | `interval_for`, `project` | awk |
| Stamp file | `mark` and the read before the gate | bash |
| Table parse (`win`, `reason`) | the script | awk over `clusage usage` text |
| Verdict and deny text | `check`, `deny`, `retry`, `stop`, `nodata` | bash |
| Config | `clusage guard-config`, read key by key | Go plus bash |
| install / uninstall / status | `manage` | python3 inside bash |
| Locating the script | `hookScript()` in `hook.go` | Go |
| Behaviour tests | `hooks/clusage-guard.test.sh`, 680 lines | bash |
| End to end test | `guard_e2e_test.go`, skipped on Windows | Go plus bash |

## Target Shape

```
settings.json ──► clusage hook run          (recommended registration)
             └──► ~/.claude/hooks/clusage-guard.sh   (legacy entries only)
                        exec clusage hook run "$@"
```

- `clusage hook run` reads the payload on stdin, dispatches on `hook_event_name`, and prints the same JSON the script prints today. It reads usage in process, so there is no child `clusage usage` call and no text table to parse.
- `clusage hook install|uninstall|status` edit `settings.json` in Go.
- `clusage hook interval <5h> <7d>` and `clusage hook project <pct> <rate> <cut>` replace `--interval` and `--project`, for debugging and for the README table.
- `clusage guard off|on|status` replaces `touch`/`rm` on the off switch. The deny text names these commands, so the advice is the same on every platform. `setGuardOff` in `guardconfig.go` already does the work for the TUI toggle.

### Recommendation: register the binary, keep wrappers for compatibility only

The wrappers you asked for are cheap, and we should ship them. But install should write `clusage hook run` straight into `settings.json`, not a wrapper path:

- Scoop puts a shim `clusage.exe` on `PATH`, and Homebrew puts `clusage` in `bin`. Both survive upgrades, which is the job the symlink does today.
- No symlink means no Developer Mode requirement on Windows.
- No wrapper means no shell in the hot path. That matters on Windows, where a Git Bash start costs 100 to 300 ms per tool call.

The wrappers then exist for two cases:

| File | Content | Purpose |
|---|---|---|
| `hooks/clusage-guard.sh` | `exec clusage hook run "$@"`, with the old `--install` style flags mapped onto subcommands | Existing installs registered `bash '~/.claude/hooks/clusage-guard.sh'`. They keep working after `brew upgrade`, before the user reruns install. |
| `hooks/clusage-guard.cmd` | `@clusage.exe hook run %*` | A user who wants a fixed file path to register on Windows. |

`clusage hook install` migrates an old entry: it finds the entry by the `clusage-guard` or `clusage hook run` marker and rewrites the command, as the Python code does today.

To confirm before Phase 3: how Claude Code on native Windows runs a hook `command` (Git Bash, `cmd.exe`, or PowerShell). The answer decides the quoting of the command string and whether the `.cmd` wrapper is useful at all. Test on a Windows machine with a `command` that prints `$0` and `%COMSPEC%`.

## Global Constraints

- The deny text, the resume text, the exit codes and the JSON shapes stay byte for byte the same as the script, apart from the off switch advice. Agents and users already read this text.
- Every degraded path still denies. A panic, a failed read or a missing window must print a deny, never exit silently. Wrap `hook run` in a `recover` that prints the NODATA deny, because a dead hook lets the call through.
- Every bad config value falls back as it does now (see the long comment above `INTERVAL` in the script). Port that rule, and its tests, exactly.
- `settings.json` keeps its key order and its unknown keys. `encoding/json` into a `map` loses the order, so use a small ordered map (a `json.Decoder` token walk into a slice of key/value pairs) or edit with `json.RawMessage` at the top level and rebuild only `hooks`.
- Commit messages follow Conventional Commits. Prose follows Simplified Technical English, as in the rest of the repo.
- Run `go test ./...` and `bash hooks/clusage-guard.test.sh` before every commit until Phase 4 retires the bash suite.

## Phases

### Phase 1: the Go decision core, no behaviour change

New `guard.go` and `guard_test.go`.

- [ ] `guardSettings` resolves env over config over default, with the fallback rules above. `guardconfig.go` already resolves most of this for the Config tab. Reuse it so the TUI and the hook cannot disagree.
- [ ] `intervalFor(p5, p7 float64, s guardSettings) int` and `project(p, rate, cut float64) (int, bool)`. Port the awk exactly, including `int(x + 0.5)` rounding and the floor of one.
- [ ] `stamp` read and write. Path is `CLUSAGE_GUARD_STATE`, else `os.TempDir()/clusage-guard-<user>.stamp`, where user comes from `os/user` and falls back to `x`. Keep the five-field text format so a bash hook and a Go hook can share the file during a mixed upgrade. Point `diagnose.go` (the stamp lookup near line 828) at the same helper.
- [ ] `verdict(windows []Window, s guardSettings) decision` returns OK, SOFT, HARD, SPENT or NODATA plus the window, percent, status, rates and reset text. Feed it the same structure `clusage usage` renders, not the table text.
- [ ] Deny text builders `denyHard`, `denySoft`, `stop`, `nodata`, `retry`, `trend`, `overage`. Copy the strings from the script.
- [ ] `CLUSAGE_GUARD_FIXTURE` still works: parse the fixture as usage table text with a Go port of `win` and `reason`. This parser exists only for tests, so the bash suite keeps passing against the Go hook in Phase 2.

Port the tables from `clusage-guard.test.sh` into `guard_test.go` as they land: the interval table, the bad bound cases, the projection cases, the verdict cases.

### Phase 2: `clusage hook run`, still registered through the script

- [ ] `hook run` reads stdin with a 2 second limit (a goroutine plus `time.After`, since `os.Stdin` has no deadline on every platform). Skip the read when stdin is a terminal (`os.Stdin.Stat()` has `ModeCharDevice`).
- [ ] SessionStart goes to the resume report. PreToolUse, or no payload, goes to the guard. Port the order of checks: disable env, off switch, stamp gate, allow list, check, pause loop, deny.
- [ ] Read usage in process through the same code path as `clusage usage -threshold N`, so failures still land in the failures table and show on the Config tab.
- [ ] The pause loop sleeps `POLL` and rechecks with no cache, up to `MAXWAIT`.
- [ ] Top level `recover` prints the NODATA deny.
- [ ] Replace the body of `hooks/clusage-guard.sh` with the one-line wrapper. Run the bash suite against it. Every case must pass unchanged. This is the parity proof.
- [ ] Update `guard_e2e_test.go` to call `clusage hook run` directly, and drop its Windows skip.

### Phase 3: install, uninstall, status in Go

- [ ] Port `manage` to Go with the ordered map. Same `EVENTS` table: PreToolUse `*` with timeout `MAXWAIT + 15`, SessionStart `resume|fork` with timeout 10.
- [ ] The command written is `clusage hook run`. Where `os.Executable()` is not on `PATH`, write its absolute path, quoted for the shell Claude Code uses on that platform.
- [ ] Install rewrites any entry whose command holds `clusage-guard` or `clusage hook run`, and removes the old symlink if it points at a clusage script. It never removes a real file.
- [ ] Status reports the entries, the command, and whether that command resolves. The Cellar warning goes away, since nothing links into the Cellar any more.
- [ ] `clusage guard off|on|status`, and the deny text and `help.go` name them instead of `touch` and `rm`.
- [ ] `clusage doctor` recognises the new command form.
- [ ] Delete `hookScript()` and `hookCandidates()` from `hook.go`, or keep them only to find a legacy link for cleanup.

### Phase 4: Windows in CI and in the bucket

- [ ] Add a `windows-latest` job that runs `go test ./...`. Today the release workflow tests on Ubuntu only.
- [ ] Port the rest of the bash suite to Go and delete `hooks/clusage-guard.test.sh`. Keep `clusage-guard.sh` as the wrapper.
- [ ] Optional: add `windows arm64` to the release build and to `bucket/clusage.json`.
- [ ] Update the scoop manifest notes: drop "not supported on Windows yet", and add `clusage hook install` as a setup step.
- [ ] README: move the hook section off bash, and update the `--interval` example.

## Risks

| Risk | Mitigation |
|---|---|
| A Go start per tool call is slower than a cached bash check | The stamp gate runs before any database open. Measure: the README claims about 20 ms for a cached bash check, and a Go binary that reads one small file should match it. |
| Two stamp writers during a mixed upgrade | Same file format and same path, and the last writer wins, which is what happens today with two sessions. |
| A shim that does not forward stdin or the exit code | Scoop shims forward both. Check once in the Windows CI job with a test that pipes a payload through the shim. |
| Deny text drift between the Go port and the script | Phase 2 runs the unchanged bash suite against the Go hook before the script is removed. |
